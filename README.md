# Gecko Reminder 🦎

Прототип интеграции Home Assistant: дневник кормлений одного питомца и карточка с крупными ячейками календаря. Первые варианты корма подобраны для эублефара. Это журнал фактических кормлений, без расписания и уведомлений.

В каждой записи: дата, вид насекомого, количество, добавка и необязательная заметка. Можно добавить несколько кормлений в день, отредактировать или удалить запись. Добавки: без добавки, кальций, кальций + D3, витамины. Выбор добавок в журнале не является рекомендацией по рациону.

Интерфейс на русском, учитывает тему HA. На узком экране календарь прокручивается горизонтально, чтобы ячейки оставались крупными. Для настенного планшета рекомендуется широкая карточка.

## Быстро посмотреть без Home Assistant

В папке проекта запустите:

```sh
python3 -m http.server 8099 --bind 127.0.0.1
```

Откройте <http://localhost:8099/demo.html>. Здесь работает та же карточка с демонстрационным хранилищем браузера: можно добавить кормление, изменить его, удалить и перезагрузить страницу. Кнопка «Сбросить демо» возвращает примеры. Примеры — иллюстрация интерфейса, не график кормлений. Остановка сервера — Ctrl+C.

**В демо данные остаются в этом браузере; в установленной интеграции — в Home Assistant. Демо не переносит записи в HA.**

## Установить сейчас вручную

Нужен Home Assistant Core **2025.1 или новее**, в том числе HA OS и HA Container. Это custom integration и Lovelace-карточка, не Supervisor add-on. Node.js, npm и сборка для установки не нужны.

1. Скопируйте папку `custom_components/gecko_reminder` из проекта в каталог конфигурации HA:

   ```text
   /config/custom_components/gecko_reminder/manifest.json
   /config/custom_components/gecko_reminder/frontend/gecko-feeding-card.js
   ```

   Для HA Container `/config` — каталог конфигурации, примонтированный в контейнер; на хосте путь может отличаться. Копируйте **всю** папку интеграции со вложенными файлами.

2. Перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Gecko Reminder**. Введите имя питомца.
4. Найдите созданный датчик **Feedings** в сущностях интеграции и скопируйте его `entity_id`. Обычно это `sensor.gecko_reminder_feedings`, но HA может назначить другое имя.
5. Включите **Расширенный режим** в своём профиле. Откройте **Настройки → Панели → меню ⋮ → Ресурсы → Добавить ресурс**:

   - URL: `/gecko_reminder/gecko-feeding-card.js?v=0.1.0`
   - Тип: **JavaScript Module**.

   Если ресурсы у вас управляются YAML, добавьте ресурс в **существующий** раздел `lovelace` в `configuration.yaml`, сохранив остальные настройки и ресурсы:

   ```yaml
   lovelace:
     resources:
       - url: /gecko_reminder/gecko-feeding-card.js?v=0.1.0
         type: module
   ```

6. На нужной панели выберите **Редактировать → Добавить карточку → Вручную**:

   ```yaml
   type: custom:gecko-feeding-card
   entity: sensor.gecko_reminder_feedings
   title: Эублефар · дневник кормлений
   ```

   Подставьте `entity_id` из шага 4. В режиме Sections увеличьте ширину карточки и секции через настройки компоновки; для отдельной страницы можно использовать тип представления Panel с одной карточкой.

7. Нажмите **+ Кормление** или **+** в нужной дате. Заполните поля и сохраните. Щелчок по существующему кормлению открывает редактирование и удаление с подтверждением.

## Установка через GitHub и HACS

Репозиторий: <https://github.com/LezhnevVV/gecko-reminder>. В одном репозитории находятся интеграция и её карточка. Через HACS выбирайте категорию **Integration**, а не Dashboard.

### Первая публикация

После загрузки кода в `main` дождитесь зелёной проверки **Checks** и создайте первый **Release** через GitHub: **Releases → Draft a new release → Choose a tag → Create new tag `v0.1.0` → Publish release**. Укажите ветку `main`. ZIP вручную собирать не нужно: HACS использует содержимое репозитория.

### Установка из GitHub

1. Если HACS ещё нет, установите его по официальной инструкции: <https://www.hacs.xyz/docs/use/download/download/>.
2. В HA откройте **HACS → меню ⋮ → Custom repositories**.
3. Вставьте `https://github.com/LezhnevVV/gecko-reminder`, выберите тип **Integration** и добавьте репозиторий.
4. Найдите **Gecko Reminder** в HACS, скачайте релиз и перезапустите HA.
5. Добавьте интеграцию, ресурс JavaScript и карточку по шагам 3–7 ручной установки выше. **HACS устанавливает файлы, но ресурс этой комплектной карточки нужно добавить один раз самостоятельно.**

Для перехода с ручной установки достаточно установить тот же репозиторий через HACS и перезапустить HA. Не создавайте второй ресурс и не удаляйте историю. Домен интеграции и ключ хранилища остаются прежними.

## Как обновлять

### Разработчику

1. Измените код и проверьте демо и тесты (ниже).
2. Поднимите `version` в `manifest.json`, например до `0.1.1`. Обновите номер в комментарии JS и примерах URL ресурса в документации.
3. Загрузите изменения в GitHub, дождитесь зелёной проверки **Checks** и опубликуйте новый Release с тегом `v0.1.1` на коммите с изменениями. Опубликованные теги не перезаписывайте.

### Пользователю Home Assistant

1. Сделайте резервную копию HA с конфигурацией и `.storage`.
2. Откройте HACS, обновите Gecko Reminder до нового релиза и перезапустите HA. Если релиз ещё не виден — обновите сведения о репозитории в HACS.
3. Если менялась карточка, **отредактируйте существующий ресурс**: `/gecko_reminder/gecko-feeding-card.js?v=0.1.1`. Не добавляйте дубликат. Обновите страницу с очисткой кэша; при необходимости полностью перезапустите приложение HA на телефоне.

При ручной установке замените папку `custom_components/gecko_reminder` новой версией, затем выполните те же перезапуск HA и обновление URL ресурса. Данные кормлений хранятся отдельно и при замене кода сохраняются.

Откат: в HACS выберите предыдущий релиз через повторную загрузку (**Redownload**, название зависит от версии HACS), перезапустите HA и поменяйте версию URL ресурса. При будущих изменениях формата хранилища следуйте примечаниям к релизу и восстанавливайте совместимую резервную копию при необходимости.

## Где данные и какие есть ограничения

- История сохраняется через штатный `Store` Home Assistant в `/config/.storage/gecko_reminder`; не редактируйте этот файл при работающем HA. Он входит в резервную копию конфигурации. Удаление интеграции не стирает журнал: повторное добавление подхватит записи.
- Карточка работает через авторизацию HA и действия `gecko_reminder.save_feeding` / `gecko_reminder.delete_feeding`. Публичный URL JavaScript отдаёт только код, без истории. Интеграция не обращается к внешним сервисам.
- В первой версии один питомец, одна добавка на запись. Для кормления несколькими видами насекомых добавьте несколько записей в одну дату. Будущие даты разрешены, но не вызывают уведомлений.
- История передаётся карточке целиком в атрибуте датчика. Для многолетних журналов большого объёма понадобится пагинация; в Recorder список `entries` исключён из записи, чтобы не дублировать весь дневник при каждом изменении.
- При одновременном редактировании одной записи действует последнее успешно сохранённое изменение. Одновременные добавления не теряются, ошибка записи на диск не меняет текущий журнал.
- Дневник общий для пользователей этой установки HA: отдельного разграничения доступа к питомцам нет.
- Это прототип. Минимальная версия HA заявлена по используемым API; совместимость с вашей установленной версией нужно проверить на реальном HA.

## Проверки и разработка

```sh
python3 -m unittest discover -s tests -v
node --check custom_components/gecko_reminder/frontend/gecko-feeding-card.js
node --test tests/card.test.cjs
```

Тесты журнала проверяют добавление, изменение, удаление, загрузку сохранённых данных, параллельные записи, отказ хранилища и валидацию. Тесты карточки в Node.js проверяют високосный месяц, несколько записей в день, экранирование текста, недоступность датчика, сохранность формы при обновлении состояния и обработку ошибки сохранения. GitHub Actions запускает их, компиляцию Python и проверку синтаксиса JS. Эти тесты не требуют установки HA и не заменяют проверку в браузере и работающем Home Assistant.

Перед первым релизом на тестовом HA проверьте:

- Настройку через UI и открытие карточки; добавление, исправление и удаление кормления.
- Сохранение истории после перезапуска и совпадение записей в двух браузерах.
- Выгрузку/загрузку интеграции, недоступный датчик, тему и мобильный экран.
- Обновление через HACS с сохранением данных.

Если написано **Custom element doesn't exist: gecko-feeding-card**, проверьте ресурс и откройте его URL в браузере: он должен вернуть JS. Затем обновите кэш. Если датчик недоступен, проверьте `entity_id` и загрузку интеграции в **Настройки → Система → Журналы**.
