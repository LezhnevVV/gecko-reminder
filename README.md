# Gecko Reminder 🦎

Версия **0.1.10**: Telegram-напоминания через настроенный получатель Home Assistant. В шестерёнке задаются получатель `notify.…`, время и включение уведомлений.

Версия **0.1.9**: кнопка ⚙ слева от стрелок открывает настройки периодичности. Включите подсветку и задайте интервал от 1 до 365 дней. Следующее кормление (самая поздняя запись + интервал) выделяется голубым и отмечается точкой; его дата также показана над календарём. Без записей дата не рассчитывается. Пропущенная дата не переносится сама, а будущие записи тоже участвуют в расчёте. Подсветку можно отключить. Плюсики в календаре убраны. Нажмите на пустой день, чтобы добавить кормление; на существующую запись — чтобы изменить её.

Версия **0.1.8**: адаптивный календарь с семью днями в ряд без обязательной горизонтальной прокрутки. При ширине карточки до 600 px значки и количество располагаются вертикально и уменьшаются; на широкой карточке сохраняется крупный вид. Режим переключается автоматически по ширине карточки. Убраны заголовок и верхняя кнопка «+ Кормление». Добавляйте записи через плюс в пустом дне. Для дополнительного кормления за занятую дату откройте форму из пустого дня и выберите нужную дату.

Версия **0.1.7**: значки насекомых увеличены до 30 px, количество — до 18 px. В узких ячейках значок добавки переносится на следующую строку, чтобы элементы не перекрывались.

Версия **0.1.6**: насекомые в календаре обозначаются значками с количеством справа, например «🦗 × 5». Название вида доступно при наведении и в форме. При создании и редактировании записи допустимо целое количество от 1 до 99; ограничение действует и в интерфейсе, и на сервере. Ранее сохранённые записи не изменяются.

Версия **0.1.5**: минимальная высота дня уменьшена со 145 до 100 px, сокращены вертикальные отступы. Значок добавки расположен рядом с кормлением, а не под ним. Дни с несколькими записями увеличиваются по содержимому, чтобы записи оставались видны.

Версия **0.1.4**: добавки в календаре показаны круглыми цветными значками: голубая косточка — кальций, жёлтое солнце — кальций + D3, фиолетовая капсула — витамины, серый минус — без добавки. Полное название доступно при наведении и для экранных дикторов. В форме редактирования сохранены текстовые названия.

Версия **0.1.3**: в днях с кормлениями плюс скрыт; записи расположены под датой. Начиная с 0.1.8 дополнительную запись можно добавить через плюс в пустом дне, изменив дату в форме.

Версия **0.1.2**: крупный плюс по центру ячейки, зелёный фон дней с кормлениями и бледно-розовый — без кормлений. Надпись GECKO REMINDER над заголовком убрана. После обновления измените URL ресурса карточки на `/gecko_reminder/gecko-feeding-card.js?v=0.1.10`.

Версия **0.1.1** исправляет ошибку импорта интеграции из-за обращения к отсутствующему валидатору `voluptuous.IsInstance`. Если в 0.1.0 мастер настройки выдаёт `Invalid handler specified`, обновите интеграцию и полностью перезапустите Home Assistant. JavaScript-карточка в этом исправлении не менялась.

Прототип интеграции Home Assistant: дневник кормлений одного питомца и карточка с крупными ячейками календаря. Первые варианты корма подобраны для эублефара. Это журнал кормлений с расчётом следующей даты по заданному интервалу, с необязательными Telegram-напоминаниями.

В каждой записи: дата, вид насекомого, количество, добавка и необязательная заметка. Можно добавить несколько кормлений в день, отредактировать или удалить запись. Добавки: без добавки, кальций, кальций + D3, витамины. Выбор добавок в журнале не является рекомендацией по рациону.

Интерфейс на русском, учитывает тему HA. На узком экране календарь показывает все семь дней недели, используя компактные ячейки и вертикальное расположение значков. Для настенного планшета рекомендуется широкая карточка.

## Быстро посмотреть без Home Assistant

В папке проекта запустите:

```sh
python3 -m http.server 8099 --bind 127.0.0.1
```

Откройте <http://localhost:8099/demo.html>. Здесь работает та же карточка с демонстрационным хранилищем браузера: можно добавить кормление, изменить его, удалить и перезагрузить страницу. Кнопка «Сбросить демо» возвращает примеры. Примеры — иллюстрация интерфейса, не график кормлений. Остановка сервера — Ctrl+C.

**В демо данные остаются в этом браузере; в установленной интеграции — в Home Assistant. Демо не переносит записи в HA.**

## Установить сейчас вручную

Нужен Home Assistant Core **2025.1 или новее**, в том числе HA OS и HA Container. Это custom integration и Lovelace-карточка, не Supervisor add-on. Node.js, npm и сборка для установки не нужны.

1. Скопируйте папку `custom_components/gecko_reminder` из проекта в каталог конфигурации HA:

   ```text
   /config/custom_components/gecko_reminder/manifest.json
   /config/custom_components/gecko_reminder/frontend/gecko-feeding-card.js
   ```

   Для HA Container `/config` — каталог конфигурации, примонтированный в контейнер; на хосте путь может отличаться. Копируйте **всю** папку интеграции со вложенными файлами.

2. Перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Gecko Reminder**. Введите имя питомца.
4. Найдите созданный датчик **Feedings** в сущностях интеграции и скопируйте его `entity_id`. Обычно это `sensor.gecko_reminder_feedings`, но HA может назначить другое имя.
5. Включите **Расширенный режим** в своём профиле. Откройте **Настройки → Панели → меню ⋮ → Ресурсы → Добавить ресурс**:

   - URL: `/gecko_reminder/gecko-feeding-card.js?v=0.1.10`
   - Тип: **JavaScript Module**.

   Если ресурсы у вас управляются YAML, добавьте ресурс в **существующий** раздел `lovelace` в `configuration.yaml`, сохранив остальные настройки и ресурсы:

   ```yaml
   lovelace:
     resources:
       - url: /gecko_reminder/gecko-feeding-card.js?v=0.1.10
         type: module
   ```

6. На нужной панели выберите **Редактировать → Добавить карточку → Вручную**:

   ```yaml
   type: custom:gecko-feeding-card
   entity: sensor.gecko_reminder_feedings
   title: Эублефар · дневник кормлений
   ```

   Подставьте `entity_id` из шага 4. В режиме Sections увеличьте ширину карточки и секции через настройки компоновки; для отдельной страницы можно использовать тип представления Panel с одной карточкой.

7. Нажмите на пустой день календаря. При необходимости измените дату в форме. Заполните поля и сохраните. Щелчок по существующему кормлению открывает редактирование и удаление с подтверждением.

## Установка через GitHub и HACS

Репозиторий: <https://github.com/LezhnevVV/gecko-reminder>. В одном репозитории находятся интеграция и её карточка. Через HACS выбирайте категорию **Integration**, а не Dashboard.

### Первая публикация

После загрузки кода в `main` дождитесь зелёной проверки **Checks** и создайте первый **Release** через GitHub: **Releases → Draft a new release → Choose a tag → Create new tag `v0.1.0` → Publish release**. Укажите ветку `main`. ZIP вручную собирать не нужно: HACS использует содержимое репозитория.

### Установка из GitHub

1. Если HACS ещё нет, установите его по официальной инструкции: <https://www.hacs.xyz/docs/use/download/download/>.
2. В HA откройте **HACS → меню ⋮ → Custom repositories**.
3. Вставьте `https://github.com/LezhnevVV/gecko-reminder`, выберите тип **Integration** и добавьте репозиторий.
4. Найдите **Gecko Reminder** в HACS, скачайте релиз и перезапустите HA.
5. Добавьте интеграцию, ресурс JavaScript и карточку по шагам 3–7 ручной установки выше. **HACS устанавливает файлы, но ресурс этой комплектной карточки нужно добавить один раз самостоятельно.**

Для перехода с ручной установки достаточно установить тот же репозиторий через HACS и перезапустить HA. Не создавайте второй ресурс и не удаляйте историю. Домен интеграции и ключ хранилища остаются прежними.

## Как обновлять

### Разработчику

1. Измените код и проверьте демо и тесты (ниже).
2. Поднимите `version` в `manifest.json`, например до `0.1.1`. Обновите номер в комментарии JS и примерах URL ресурса в документации.
3. Загрузите изменения в GitHub, дождитесь зелёной проверки **Checks** и опубликуйте новый Release с тегом `v0.1.1` на коммите с изменениями. Опубликованные теги не перезаписывайте.

### Пользователю Home Assistant

1. Сделайте резервную копию HA с конфигурацией и `.storage`.
2. Откройте HACS, обновите Gecko Reminder до нового релиза и перезапустите HA. Если релиз ещё не виден — обновите сведения о репозитории в HACS.
3. Если менялась карточка, **отредактируйте существующий ресурс**: `/gecko_reminder/gecko-feeding-card.js?v=0.1.10`. Не добавляйте дубликат. Обновите страницу с очисткой кэша; при необходимости полностью перезапустите приложение HA на телефоне.

При ручной установке замените папку `custom_components/gecko_reminder` новой версией, затем выполните те же перезапуск HA и обновление URL ресурса. Данные кормлений хранятся отдельно и при замене кода сохраняются.

Откат: в HACS выберите предыдущий релиз через повторную загрузку (**Redownload**, название зависит от версии HACS), перезапустите HA и поменяйте версию URL ресурса. При будущих изменениях формата хранилища следуйте примечаниям к релизу и восстанавливайте совместимую резервную копию при необходимости.

## Где данные и какие есть ограничения

- Периодичность сохраняется вместе с журналом и общая для всех устройств. В хранилище версии 1 добавлено необязательное поле `feeding_interval_days`: старые журналы загружаются без изменений, подсветка по умолчанию выключена. При откате на старую версию последующее сохранение может удалить только новую настройку, но не записи.
- История сохраняется через штатный `Store` Home Assistant в `/config/.storage/gecko_reminder`; не редактируйте этот файл при работающем HA. Он входит в резервную копию конфигурации. Удаление интеграции не стирает журнал: повторное добавление подхватит записи.
- Карточка работает через авторизацию HA и действия `gecko_reminder.save_feeding` / `gecko_reminder.delete_feeding`. Публичный URL JavaScript отдаёт только код, без истории. Gecko Reminder вызывает действия уведомлений HA; соединение с Telegram и токен обслуживает стандартная интеграция Telegram Bot.
- В первой версии один питомец, одна добавка на запись. Для кормления несколькими видами насекомых добавьте несколько записей в одну дату. Будущие записи разрешены и участвуют в подсветке следующей даты, но для напоминаний учитываются только кормления не позднее сегодняшнего дня.
- История передаётся карточке целиком в атрибуте датчика. Для многолетних журналов большого объёма понадобится пагинация; в Recorder список `entries` исключён из записи, чтобы не дублировать весь дневник при каждом изменении.
- При одновременном редактировании одной записи действует последнее успешно сохранённое изменение. Одновременные добавления не теряются, ошибка записи на диск не меняет текущий журнал.
- Дневник общий для пользователей этой установки HA: отдельного разграничения доступа к питомцам нет.
- Это прототип. Минимальная версия HA заявлена по используемым API; совместимость с вашей установленной версией нужно проверить на реальном HA.

## Проверки и разработка

```sh
python3 -m pip install -r tests/requirements.txt
python3 -m unittest discover -s tests -v
node --check custom_components/gecko_reminder/frontend/gecko-feeding-card.js
node --test tests/card.test.cjs
```

Тесты журнала проверяют добавление, изменение, удаление, загрузку сохранённых данных, параллельные записи, отказ хранилища и валидацию. Тесты карточки в Node.js проверяют високосный месяц, несколько записей в день, экранирование текста, недоступность датчика, сохранность формы при обновлении состояния и обработку ошибки сохранения. GitHub Actions запускает их, компиляцию Python и проверку синтаксиса JS. Эти тесты не требуют установки HA и не заменяют проверку в браузере и работающем Home Assistant.

Дополнительный тест импортирует модуль интеграции с настоящей Voluptuous и подменёнными API Home Assistant, чтобы обнаруживать ошибки построения схемы сервисов. Это не полноценный запуск HA.

Перед первым релизом на тестовом HA проверьте:

- Настройку через UI и открытие карточки; добавление, исправление и удаление кормления.
- Сохранение истории после перезапуска и совпадение записей в двух браузерах.
- Выгрузку/загрузку интеграции, недоступный датчик, тему и мобильный экран.
- Обновление через HACS с сохранением данных.

Если написано **Custom element doesn't exist: gecko-feeding-card**, проверьте ресурс и откройте его URL в браузере: он должен вернуть JS. Затем обновите кэш. Если датчик недоступен, проверьте `entity_id` и загрузку интеграции в **Настройки → Система → Журналы**.


## Напоминания в Telegram

1. Подключите стандартную интеграцию **Telegram Bot**: **Настройки → Устройства и службы → Добавить интеграцию → Telegram Bot**. Официальная инструкция: <https://www.home-assistant.io/integrations/telegram_bot/>. Создайте бота через BotFather и начните с ним диалог. Токен вводится только в настройках Telegram Bot, не в Gecko Reminder.
2. Настройте разрешённого получателя по инструкции Telegram Bot и найдите его сущность `notify.…` в HA. Если уже используется старое действие `notify.…`, оно тоже поддерживается. Для проверки подключения можно самостоятельно отправить сообщение из **Инструменты разработчика → Действия**.
3. Откройте **⚙** на календаре. Включите периодичность, задайте интервал, затем включите **Напоминать в Telegram**.
4. Выберите время и укажите получателя, например `notify.telegram_pet`. Это пример, нужно реальное имя из вашего HA. Поле предлагает имеющиеся сущности и действия `notify`; выберите именно Telegram. Не указывайте общее действие `notify.send_message` — нужна конкретная сущность получателя.
5. Сохраните. При настройке проверяется наличие получателя; тестовое сообщение автоматически не отправляется.

Напоминание работает на сервере, даже когда панель закрыта. Время соответствует часовому поясу HA. Проверка выполняется каждую минуту: если указанное время наступило и кормление пора сделать, отправляется одно сообщение за день. Если кормление не отмечено, напоминание повторяется на следующий день в то же время. Отметка кормления до отправки отменяет напоминание до следующей даты. Без истории и периодичности сообщения не отправляются.

После перезапуска HA проверяет пропущенное время и может отправить напоминание за текущий день сразу. Успешная отправка отмечается в хранилище, чтобы обычный перезапуск не приводил к повтору. Если получатель недоступен, попытка повторяется на следующей минуте. Тайм-аут вызова — 30 секунд. В редком случае обрыва после приёма сообщения Telegram или ошибки сохранения отметки с последующим перезапуском возможен повтор: внешняя доставка не гарантирует строго однократную отправку.

Новые необязательные поля хранилища версии 1: `reminder` и `last_reminder_date`. Старые журналы читаются с выключенными уведомлениями. При откате старые версии могут удалить новые настройки при сохранении, поэтому перед обновлением делайте резервную копию. Демо сохраняет настройки только в браузере и не отправляет сообщения.
